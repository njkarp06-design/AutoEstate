# reporting-app/

Read-only Next.js dashboard for a non-technical client to see what the AutoEstate agent has done — one row per WhatsApp/Telegram conversation, with the raw facts sent in and the actual generated content sent back.

## Data source

Multi-tenant: one Postgres database (Prisma) shared across all customers, each with their own `Customer` row and an isolated set of `Run`/`RunMessage` rows. Each customer's dedicated Hermes instance (see `infra/`) pushes its own conversation turns here over HTTP via the `sync-to-webapp` plugin (`agent/plugins/sync-to-webapp/`) — there's no direct database or filesystem access between a customer's Hermes instance and this app.

- `POST /api/ingest` — the ingestion endpoint Hermes instances call. Authenticated with a per-customer bearer secret (`Authorization: Bearer <secret>`), generated by Terraform at provisioning time and looked up here by its SHA-256 hash (`Customer.ingestionSecretHash` — the secret itself is never stored). One `Run` per Hermes turn (`hermesTurnId`), not per session — a WhatsApp/Telegram session never resets between messages, so a session can span many unrelated listings.
- Everything else in the app (`/`, `/runs/[id]`) requires a logged-in Clerk session, scoped to the signed-in user's own `Customer` row (matched by email on first login, then by `clerkUserId` after that).
- A run's status ("Completed" vs "In progress") is based on whether it has at least one assistant message yet, not on any Hermes-side session state.

## Running locally

Requires `DATABASE_URL` (Postgres) and Clerk keys in `.env.local` — see `prisma.config.ts` and `lib/customer.ts` for what's read.

```bash
npm install
npx prisma generate
npm run dev
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). Note: on this machine, `localhost` resolves to an unrelated app running on the same port over IPv6 — always use `127.0.0.1` explicitly.

To register a new customer after provisioning their Hermes instance (see `infra/modules/hermes-instance/README.md`), use `scripts/provision-customer.ts`.

## Structure

- `prisma/schema.prisma` — `Customer`, `Run`, `RunMessage` models.
- `lib/db.ts` — customer-scoped Prisma queries (`getRuns`, `getRun`).
- `lib/customer.ts` — resolves the logged-in Clerk user to their `Customer` row.
- `app/api/ingest/route.ts` — ingestion endpoint for Hermes instances.
- `app/page.tsx` — list of runs.
- `app/runs/[id]/page.tsx` — full transcript for one run, with the generated content rendered as markdown.

Both page routes are forced dynamic (`export const dynamic = "force-dynamic"`) so they always reflect the live database rather than a build-time snapshot.
