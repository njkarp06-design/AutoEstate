# agent/

Hermes agent configuration and skills for AutoEstate. Self-hosted (own API keys, not the Nous Portal) — see [CLAUDE.md](../CLAUDE.md) for why.

- Installed locally (Phase 1 complete): Hermes CLI, self-hosted with a direct Anthropic API key, provider pinned to `anthropic`. Config lives outside this repo at `%LOCALAPPDATA%\hermes` (`HERMES_HOME`), never committed.
- `skills/real-estate/listing-to-social/` — the listing-to-social pipeline skill (Phase 2a, built and tested; hardened to v0.3.0 for sale/rental price phrasing, real photo handling (typed descriptions and real attached WhatsApp/Telegram images, treated the same way), a structured hashtag strategy, a guard against blending facts from two different properties into one response, and not upgrading stated facts into unstated condition/availability or neighborhood claims).
- `skills/real-estate/listing-status-update/` — announces a price drop or going under contract/rented on a listing already advertised via `listing-to-social`, in the same three-platform Hebrew+English format (v0.3.0). No longer handles a completed sale — that's `just-sold`.
- `skills/real-estate/just-sold/` — a celebratory, social-proof post announcing a completed sale, distinct in tone from `listing-status-update`'s factual notes; the only skill that emits `Status: Sold` in the Listing Record footer (v0.1.0).
- `skills/real-estate/listing-reengagement/` — re-promotes a listing that's still active and hasn't changed, framed as a reminder rather than a first-time introduction; emits no Listing Record footer, since nothing about the listing transitions (v0.1.0).
- `skills/real-estate/weekly-digest/` — drafts a bilingual roundup of a customer's currently active listings, reading from the reporting system's own record via the `active-listings-context` plugin rather than the agent retyping the list (v0.1.0).
- All skills live under `skills/real-estate/`, and Hermes finds them via `skills.external_dirs` in this machine's local `config.yaml` (outside the repo, machine-specific, points at the parent `skills/` folder so new skill directories are auto-discovered — set that up again on any new machine/client install). Plugins (`plugins/`) are not auto-discovered the same way — see [CLAUDE.md](../CLAUDE.md) for the manual deployment step.
- Real credentials never live in this repo at all — set them by editing `.env` directly at the path `hermes config env-path` prints (`%LOCALAPPDATA%\hermes\.env` on Windows), or via `hermes secrets` for an external secret manager (Bitwarden/1Password). `hermes config set` is for `config.yaml` settings only (e.g. `model`, `terminal.backend`) — it does not touch `.env`.
