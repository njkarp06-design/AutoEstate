# agent/

Hermes agent configuration and skills for AutoEstate. Self-hosted (own API keys, not the Nous Portal) — see [CLAUDE.md](../CLAUDE.md) for why.

- Installed locally (Phase 1 complete): Hermes CLI, self-hosted with a direct Anthropic API key, provider pinned to `anthropic`. Config lives outside this repo at `%LOCALAPPDATA%\hermes` (`HERMES_HOME`), never committed.
- `skills/real-estate/listing-to-social/` — the listing-to-social pipeline skill (Phase 2a, built and tested; hardened to v0.5.0 for sale/rental price phrasing, real photo handling (typed descriptions and real attached WhatsApp/Telegram images, treated the same way), a structured hashtag strategy, a guard against blending facts from two different properties into one response, and not upgrading stated facts into unstated condition/availability or neighborhood claims).
- `skills/real-estate/listing-status-update/` — announces a price drop or going under contract/rented on a listing already advertised via `listing-to-social`, in the same three-platform Hebrew+English format (v0.5.1). No longer handles a completed sale — that's `just-sold`. Can be pointed at a listing by name instead of restated facts (the locator lookup, PR #26).
- `skills/real-estate/just-sold/` — a celebratory, social-proof post announcing a completed sale, distinct in tone from `listing-status-update`'s factual notes; the only skill that emits `Status: Sold` in the Listing Record footer (v0.3.1).
- `skills/real-estate/listing-reengagement/` — re-promotes a listing that's still active and hasn't changed, framed as a reminder rather than a first-time introduction; emits no Listing Record footer, since nothing about the listing transitions (v0.2.1).
- `skills/real-estate/weekly-digest/` — drafts a bilingual roundup of a customer's currently active listings, reading from the reporting system's own record via the `active-listings-context` plugin rather than the agent retyping the list (v0.1.0).
- `skills-buyer/real-estate/buyer-inquiry/` — the **inbound** skill (v0.4.0): answers a prospective buyer's factual questions from real listing data, is honest about SOLD/UNDER_CONTRACT, defers anything human to the agent and captures the buyer as a reachable lead — including amenity questions, since the footer's optional `Features` line carries them through to the buyer bot. Since v0.4.0 it also resolves a **listing ref code** (`REF-V42TS`) from the buyer's first message, which arrives prefilled via the ad's WhatsApp deep link — an exact match that skips disambiguation entirely; the area-matching branch remains as the fallback. Deliberately **not** under `skills/` — see below.
- `profiles/autoestate-buyer/` — the committed, commented config for the buyer-facing Hermes profile (`config.yaml`, `SOUL.md`, a secret-stripped `.env.example`, and a README explaining the isolation layers). The live profile's own `config.yaml` is machine-rewritten and loses comments, so this copy is the source of truth.

**Two skill roots, on purpose.** `skills/` is the **operator** set (five outbound skills, all of which can mutate the `Listing` table); `skills-buyer/` holds only `buyer-inquiry` and is what the public buyer instance points at. The split is structural, not cosmetic: the Hermes sender allowlist is enforced inside the vendored adapter and sender identity never reaches a skill, so a buyer instance cannot be allowed to load the outbound skills. Each profile's `skills.external_dirs` points at exactly one of these roots.

- Hermes finds skills via `skills.external_dirs` in this machine's local `config.yaml` (outside the repo, machine-specific, points at the appropriate root so new skill directories under it are auto-discovered — set that up again on any new machine/client install). Plugins (`plugins/`) are not auto-discovered the same way — see [CLAUDE.md](../CLAUDE.md) for the manual deployment step.
- Real credentials never live in this repo at all — set them by editing `.env` directly at the path `hermes config env-path` prints (`%LOCALAPPDATA%\hermes\.env` on Windows), or via `hermes secrets` for an external secret manager (Bitwarden/1Password). `hermes config set` is for `config.yaml` settings only (e.g. `model`, `terminal.backend`) — it does not touch `.env`.
